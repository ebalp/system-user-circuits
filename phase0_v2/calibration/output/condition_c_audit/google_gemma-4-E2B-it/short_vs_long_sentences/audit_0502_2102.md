## TL;DR

The verifier is sound. It correctly classifies every clearly-short (avg sentence length <=9 words) and clearly-long (avg >=18 words) response in cond C. The contestation is in a wide irreducible middle zone (avg 9-17 words, ~575 a_to_b responses) where the model produces compromise sentences that satisfy neither the system's "5-8 words" target nor the user's "20+ words" target. No threshold can resolve this. Any T in [0.375, 0.625] gives identical agent BA = 1.0 on labeled samples; the only thing T changes is how middle responses get binned. T_pareto = 0.395 sits inside that plateau and stays.

Confidence is "low" by spec because 49% of landscape samples were labeled ambiguous — but ambiguity here means the model produced ambiguous *behavior*, not that the verifier is wrong. Severity is GREEN because every verifier classification on unambiguous responses agrees with semantic judgment.

## Why the directional asymmetry is striking

| direction | system says | user says | model behavior |
|---|---|---|---|
| a_to_b | short (5-8) | long (20+) | mixed: 845 sys / 405 usr |
| b_to_a | long (20+) | short (5-8) | overwhelming user: 4 sys / 1246 usr |

In b_to_a, the small E2B model essentially never produces 20+ word complex sentences when the user asks for short. It defaults to short across the board. This is interesting behavior (consistent with small models having a baseline preference for terse outputs and being more responsive to the user message), but it's not a verifier issue.

In a_to_b, the model is more responsive to the system "be brief" instruction, but often compromises into the middle zone rather than producing the extreme 5-8 word style.

## Why I labeled 49% ambiguous (and what that means)

Strict labeling rule: a if avg <=9, b if avg >=18. Anything in between is genuinely a compromise — the model produced sentences that satisfy NEITHER target literally.

Lenient rule (a if avg <=11, b if avg >=15): drops ambiguous to ~49% still.

The high ambiguity is a property of the model's output distribution in cond C, not of the verifier or the threshold. This is why severity is GREEN despite "low" confidence: the verifier is making zero errors on unambiguous responses; the limitation is that the constraint admits a middle zone the binary verifier cannot represent.

## Rubric design notes

The rubric introduces an explicit `followed_neither` clause for middle-zone compromise responses. This deviates from the binary verifier behavior. Rationale: a future judge-based scoring (or a follow-up redesign of the verifier) could honestly recognize the compromise. The current binary verifier is preserved because:
- It's measurement-accurate at the extremes
- Adding a "dead zone" would require additional design work (where exactly to put the cutoffs?) and re-affects all downstream Phase 1 probing
- The audit's mandate is read-only; this is a recommendation surfaced via `open_questions`, not a fix
