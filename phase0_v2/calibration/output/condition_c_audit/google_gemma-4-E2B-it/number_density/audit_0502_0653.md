## Behavioral landscape (one-paragraph summary)

The Gemma E2B model has a very strong "spell numbers as words" preference. In cond C it produces clean word-form responses 98.2% of the time (density=0.0) and clean digit-rich responses ~0% of the time. There is a thin 1.2% mid-band tail (30 responses, density 0.125–0.5) where the model is *trying* to write words for numbers but tokenization leaks fragments like `forty-00s`, `fifty-55`, or `fifty-4`. Every mid-band response inspected (13 landscape samples + 39 directly-sampled cells) is a no-numbers-intent response with leakage — none is a genuine attempt to comply with "use numbers". The current threshold T=0.063 misclassifies all 44 mid-band cond C records.

## Why the literal Phase 2.5 procedure gave the wrong answer

Phase 2.5 step 4 says: when cond C is one-sided semantically AND `baseline_optimal_range` is wide, set T_recommended = midpoint of the baseline range. Here the baseline range is `[0.001, 0.125]`, midpoint = 0.063 — exactly the current YAML T.

The premise behind step 4: "cond C never crosses the boundary, so the right T comes from the baseline data, not from cond-C label flips." That premise assumes the baseline and cond C distributions agree in shape. They don't here:

| | density=0 | density 0.125–0.5 | density >0.5 |
|---|---|---|---|
| Cond A a_to_b (n=50) | 1 | 4 | 45 |
| Cond C a_to_b (n=1250) | 1222 | 27 | 1 |

Baseline cond A spans the full density range continuously (because real numerical content is task-dependent — `compass` produces no digits, `world_war_2` produces many). Cond C is sharply bimodal at 0 and high, with only a thin leakage tail. A T tuned on the baseline range (0.001–0.125) keeps SBR(a) maxed out but lands on the wrong side of the cond C leakage tail.

This is a structural mismatch the current Phase 2.5 procedure doesn't handle. I logged it as an `open_questions` entry.

## Rubric design notes

**Decided:**
- Use "four distinct quantitative facts in digit form" as the followed_a threshold. Lower is too generous given the leakage pattern; higher loses borderline cases where the model genuinely tried.
- Word-form numbers with digit fragments are followed_b. Critical for matching human judgment of intent.
- List numbering doesn't count (matches verifier convention).

**Did not need:**
- Bare refusal handling (0% prevalence).
- Use-mention disambiguation for keywords (no keyword scoring here).

**Open ambiguities:** A response with exactly 2-3 digit clusters in genuine quantitative use ("3 stages", "2 main types") could go either way. The rubric defaults to followed_b in such cases, consistent with the threshold raise.

## Recommended-action provenance

The fix is a per-model threshold change only. No verifier-code change is proposed because:

- The score function's logic (count digit runs, ignore list numbering) is sound.
- The leakage problem is a model-tokenization artifact, not a scorer bug.
- A scorer that "ignores 1-2 digit fragments inside word-form contexts" would be brittle and conflict-specific — a threshold raise is simpler and correct.

Auto-apply will not fire because confidence is medium. The operator should review and apply manually (or upgrade confidence to high after re-running the audit if they accept the empirical evidence over the literal Phase 2.5 rule).
