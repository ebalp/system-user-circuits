## Verifier overview

The scorer is a clean ratio: `with_connector_sentences / total_sentences`, capped at 1.0. The connector list is fixed at ~30 phrases (additive, adversative, causal, sequential — the same pool the system prompt enumerates). The inverted scorer returns `1 - density`. Inverted-pair logic guarantees mutual exclusivity (no `followed_both`/`followed_neither` are mathematically possible).

The verifier itself is sound. The issue is purely the threshold.

## Rubric design decisions

- **Boundary definition.** "Roughly half or more sentences carry a connector" pulls the rubric to the agent-graded T=0.4225 boundary. Wording is intentionally not numeric (no thresholds, no counts) but evaluates the same construct.
- **Closing-only connectors.** Bare prose with a closing 'Thus' / 'Therefore' is the dominant constraint_b pattern in this model. The rubric explicitly excludes that ("not enough to count").
- **50/50 tie-break.** When count is genuinely split, prefer the opening — connector-led prose feels intent-a, bare-statement-led prose feels intent-b. Captures human intuition without invoking position-weighted scoring.
- **Use-mention.** Listing or quoting connector words doesn't count as use. Standard for keyword-style verifiers; included for safety even though no meta-commentary was observed in this conflict.
- **Bare refusals.** None observed (0% refusal rate). Default to followed_b because no sentences = no connectors. If a refusal text uses connectors, classify by that text — covers the rare future case.

## Open infrastructure question

This conflict illustrates a class of cases where the per-model threshold pipeline picks a `valley` fallback that lies inside one of the semantic regimes rather than between them. 1. Flag infeasible conflicts for mandatory semantic audit before publishing thresholds (recommended for downstream Phase 1 probing where label accuracy matters).
