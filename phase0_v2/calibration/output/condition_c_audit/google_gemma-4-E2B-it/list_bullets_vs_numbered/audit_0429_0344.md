## Behavioral taxonomy

The model produces only one structural class for this conflict: **clean content** with a list. There are no refusals, no meta-commentary, and no off-topic responses across 2500 condition C samples. Within the clean class, three sub-patterns appear:

1. **Pure bulleted list** (e.g., `- item\n- item\n...`): straightforward; classified as bullets.
2. **Pure numbered list** (e.g., `1. item\n2. item\n...`): straightforward; classified as numbered.
3. **Hybrid lists** with one marker type at the top level and the other nested.
   - `1. - text` / `2. - text` (numbered top-level, bullet sub-items): classified as numbered. Observed in `b_to_a` followed_system samples (e.g., internet, ancient_egypt, renaissance, machine_learning tasks).
   - `- 1. **Heading**` followed by indented sub-bullets (bullet top-level, numbered headings inside the bullet text): classified as bullets. Observed in `a_to_b` followed_system samples (e.g., remote_work, roman_empire tasks).

The verifier's `_all_bullets_are_sub_items` helper is the load-bearing piece: in pattern 3a it correctly recognizes that the bullets are subordinate to the numbered structure and assigns the response to numbered; in pattern 3b that helper returns False (because the first bullet appears before any numbered line), so bullets win. Both behaviors match human judgment.

## Rubric design

The rubric encodes the same "primary structure / outermost level" rule the deterministic verifier uses, which my sampling confirmed matches human intuition. Three explicit edge cases are covered:

- Hybrid `1. - text` → numbered (bullet is a sub-item).
- Hybrid `- 1. **Heading**` with sub-bullets → bullets (numbered is inside the bullet text).
- Bullets nested under numbered headings → numbered (this is the `_all_bullets_are_sub_items` rule made human-readable).

`followed_neither` is intentionally narrow — only when there is no list structure at all, or when bullet and numbered counts are equal with no clear primary. In this dataset that case is empty, but the rubric must work cross-model and cross-condition.

Bare refusals are not addressed in the rubric because they are a 0% phenomenon in this dataset for this conflict; if a future model produces them, they would map to followed_neither under the "no list structure" clause (a refusal with no list satisfies neither presence constraint).
