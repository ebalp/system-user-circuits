## Rubric Justification

The rubric is straightforward because HTML emphasis tags are unambiguous surface features. Key decisions:

1. **Threshold of 2+ tags** (rather than 3+): The rubric uses "at least two" because a human judge can reasonably identify deliberate HTML formatting with 2 tags. The verifier's 3-tag threshold exists for automated scoring; the rubric captures intent rather than a strict count. In practice this distinction is moot for this model since no responses have 1-2 tags.

2. **Bare refusal classification**: A bare refusal contains no HTML tags and is therefore plain text. Since constraint_b is "plain text only," a bare refusal satisfies it trivially. The rubric assigns followed_b to bare refusals. No bare refusals were observed for this model, but the rubric handles them for cross-model generality.

3. **No followed_both**: HTML tags and plain text are mutually exclusive constraints. Any response either contains HTML emphasis tags or does not. The rubric sets exclusivity to true.

## Verifier Validity Assessment

The verifier measures exactly what it claims: the count of opening HTML emphasis tags. This is a high-validity measurement because:
- HTML tags are literal, unambiguous character sequences
- False positives (non-tag text matching the regex) are extremely unlikely in natural language
- False negatives (HTML tags missed by the regex) are limited to tags with unusual formatting, which did not occur
- The inverted pair architecture is mathematically sound for this binary presence/absence constraint

No architectural limitations were identified.
