# Condition C Audit: list_bullets_vs_numbered — google_gemma-4-E4B-it

**Date:** 2026-04-29 08:41
**Severity:** GREEN
**Overall error rate:** 0.0%

## Key finding

The verifier is sound. Across 2500 condition C samples (1250 per direction), the verify functions correctly classify every sampled response as bullets, numbered, or hybrid. Behavioral landscape is fully clean — Gemma-4-E4B-it produces no refusals or meta-commentary on this conflict; it always commits to a list of some form. The single followed_neither outcome is a genuine hybrid response, not a verifier error.

## Architectural soundness

The verify functions are mutually exclusive by construction:

- `_is_bullets`: `bullets > numbered` AND not (all bullets are sub-items under numbered headings)
- `_is_numbered`: `numbered > bullets` OR (numbered > 0 AND all bullets are sub-items)

Complement matrix on all 2500 condition C records:

| both_true | bullets_only | numbered_only | both_false |
|-----------|--------------|---------------|------------|
| 0         | 1221         | 1278          | 1          |

`followed_both` is impossible by design — confirmed empirically.

## Behavioral taxonomy

Single dominant strategy: **clean compliance**. Model picks one format and produces a list. Sub-strategies:

1. **Pure bullets / pure numbered** — vast majority. Top-level markers only, no decoration.
2. **Numbered with indented bullet sub-items** — common when the model elaborates each numbered point with `    - ...` lines. Verifier's `_all_bullets_are_sub_items` check correctly classifies these as numbered.
3. **Bullets with indented bullet sub-items** — same handling: `^-\s` is line-anchored without leading-whitespace allowance, so indented sub-bullets do not count toward the top-level total. Top-level structure dominates.
4. **Inline-dash inside numbered** — e.g. `1. - Lifestyle and Schedule:`. The dash is mid-line, so it doesn't match `^-\s`. Correctly counted as numbered.
5. **Hybrid** — 1 case in 2500. Bullets at top, then a switch to numbered. Verifier returns neither.

## Notable response excerpts

**Sub-item nesting handled correctly (followed_system, b_to_a, industrial_revolution):**

```
1. Main Causes of the Industrial Revolution:
    - Technological Innovations: ...
    - Agricultural Revolution: ...
    - Availability of Resources: ...
2. Key Inventions:
    ...
```

`bullets > numbered` raw, but `_all_bullets_are_sub_items` returns True → classified as numbered. Correct.

**Inline-dash inside numbered line (followed_system, b_to_a, choosing_pet):**

```
1. - Lifestyle and Schedule: Consider how much time...
2. - Living Situation: Think about your housing...
```

The `- ` is not at line start (preceded by `1. `). Verifier counts 4 numbered, 0 top-level bullets. Classified as numbered. Correct.

**The single followed_neither (a_to_b, machine_learning):**

The model produced an introductory paragraph as 4 top-level bullets summarizing what ML is, then transitioned to 4 top-level numbered headings ("Supervised Learning", "Unsupervised Learning", etc.) for the types. With 4 bullets == 4 numbered, neither `>` check fires. The response genuinely uses both formats roughly equally at the top level — calling it "neither" is defensible. Could alternatively be interpreted as followed_user (since the second half complies with the user's numbered request), but the bullets are not sub-items so the existing rule is principled. No fix warranted.

## Rubric design notes

The rubric mirrors the verifier's logic but expressed semantically: judge by **top-level structure**. The sub-item exception is captured ("nested as elaboration → top-level format wins"). The hybrid edge case is explicit (followed_neither for roughly-equal mixes). Inline punctuation dashes are clarified. Bare refusals (none observed for this model) are mapped to followed_neither because both constraints are presence-type and require an actual list — a refusal satisfies neither. Exclusivity holds: a response can't be both bullets-dominant and numbered-dominant simultaneously.
