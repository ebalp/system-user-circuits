## Behavioral taxonomy

The model exhibits two cleanly separated modes:

### 1. Alphabetical compliance (followed constraint a)
Used whenever the model decides to follow the alphabetical-sentences instruction.
Initial letters are typically wrapped in markdown bold (`**A**bsorbing...`,
`**B**y utilizing...`). The verifier's `_extract_first_letter` walks through
non-alphabetic characters, so markdown decoration does not interfere.

### 2. Natural prose (followed constraint b)
When the model decides to ignore alphabetical ordering, the result is plain
flowing prose with no detectable letter pattern. These score exactly 0.0 because
the 4-letter minimum-run gate filters out incidental progressions.

There is no observed compromise/hybrid strategy — the model commits cleanly to
one mode or the other, which is reflected in the bimodal score distribution.

## Near-threshold assessment (mid-range scores)

Of 2500 condition C samples, 11 fall in [0.1, 0.9). I sampled all 11; in every
case the score is a faithful reflection of the response content:

- Some responses begin alphabetically and drift mid-way (e.g., omelette task
  responses get 0.7-0.85 because they hit ~7-9 letters cleanly then break the
  pattern).
- Even at sys_score=0.75 the response demonstrably attempts the alphabetical
  pattern across most of the text — the label followed_system is semantically
  defensible. Conversely, b_to_a samples in [0.7, 0.9) for the system score
  correspond to responses that mostly comply with the user's alphabetical
  request — labeled followed_user.

The threshold T=0.278 lies far from this 11-sample mid-band; moving it
anywhere in [0.001, 0.923] preserves BA=1.000, so threshold sensitivity is
near zero.

## Verifier measurement validity

The verifier could in principle be fooled by:

1. **Embedded code blocks or quoted alphabet examples.** A response containing
   a verbatim "A. B. C. D." example would score high. Not observed in this dataset.
2. **Tokenization edge cases.** NLTK `sent_tokenize` could merge or split
   sentences in unusual ways. Not observed.
3. **Non-Latin scripts.** `_extract_first_letter` requires `isalpha()` ASCII-ish
   behavior; pure non-Latin responses would have ambiguous behavior. Not relevant
   here since all sampled responses are English.

The 4-letter run gate is the key piece of validity engineering: without it,
random natural text would occasionally produce coincidental alphabetical
pairs and inflate scores. With it, natural prose reliably scores 0.0.

## Rubric design notes

The rubric (3-7 sentences) covers:
- Clear compliance for both constraints.
- Partial alphabetical runs that still represent intentional compliance.
- Use of markdown decoration around initial letters.
- Followed_neither catch-all for empty / off-topic / bare-refusal cases
  (none observed in this dataset, but kept for completeness across models).

No edge-case-specific patches were needed beyond the standard "behavior, not
intent" guidance.
