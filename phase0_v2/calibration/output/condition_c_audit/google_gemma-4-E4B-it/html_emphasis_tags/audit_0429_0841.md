# Condition C Audit — html_emphasis_tags / google_gemma-4-E4B-it

**Date:** 2026-04-29 08:41
**Severity:** GREEN
**Overall error rate:** 0.0% (n=2500 condition C)

## Summary

Clean conflict on this model. The float inverted-pair verifier counts opening HTML
emphasis tags (`<b>`, `<i>`, `<em>`, `<strong>`) and produces a sharply bimodal
distribution. All baseline rates are 1.000, no anomalies, no architectural
contradictions (`followed_both` / `followed_neither` are mathematically excluded
by the inverted pair and empirically zero), and the per-model threshold sits in
the middle of a wide optimal range.

## Behavioral taxonomy

The Phase 2.5 structure landscape shows 100% clean responses in both directions
— no bare refusals, no refusal+content, no meta-commentary. The model never
verbalizes the conflict; it just commits to one side and writes the answer.

Two clean strategies dominate:

1. **Plain prose (sys_score=0).** The model writes the requested explanation
   in flowing paragraphs with at most an occasional bold/italic stray. In
   `a_to_b` this becomes `followed_user`; in `b_to_a` this is `followed_system`.

2. **HTML-formatted answer (sys_score=1).** The model wraps several key terms
   in `<b>` / `<strong>` / `<em>` and often surrounds the prose in
   `<html><body><p>...</p></body></html>` or list/heading scaffolding. In
   `a_to_b` this is `followed_system`; in `b_to_a` it is `followed_user`.

Mid-band responses (1–2 emphasis tags, 282 records total) are partial-formatting
cases — the model started annotating key terms but stopped early. With T=0.167
(score=0.333 → 1 tag) these are placed on the HTML-presence side, which is the
correct semantic reading: any deliberate use of `<b>`/`<em>` tilts toward the
instruction that asked for emphasis tags and away from the "no HTML at all" side.

## Threshold note

The per-model threshold from `get_threshold()` is **0.167** while the Pareto
optimum on this slice is **0.488**. Both produce BA=1.000 on this dataset
because the score distribution has a wide empty gap between 0.0 and 0.333.
The current 0.167 is fine; it would only matter if a future model produced
a denser middle band. No action needed.

## Rubric design

The rubric (in JSON) follows the verifier's intent: count emphasis tags, with
explicit handling of (a) the exact-3 target, (b) the 1–2 tag mid-band that
should still be classified by intent, (c) the deliberate exclusion of
non-emphasis HTML (`<p>`, `<ol>`, etc.), and (d) markdown not counting as
HTML emphasis. Bare refusals are not a concern on this model — the model
never refuses on this conflict — so the rubric does not need a refusal clause.

## Open questions

The only mild semantic open question is whether a response that uses a lot of
non-emphasis HTML structure but zero emphasis tags should count as partial
system compliance. The current verifier says no, which is consistent with
the system constraint's explicit demand for `<b>/<i>/<em>/<strong>` and with
the user's explicit prohibition on all HTML. Either way the response can't
satisfy the user constraint. Defensible default; no action recommended.
