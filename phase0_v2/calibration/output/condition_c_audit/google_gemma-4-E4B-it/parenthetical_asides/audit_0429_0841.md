## Verifier measurement validity (Phase 1 critique)

The regex `\([^()]*\S[^()]*\)` matches any parens with non-empty inner content. Considered false positives:
- Smileys like `:)` or `(:` — not matched (require both opening and closing). Good.
- Empty parens `()` — not matched (require non-whitespace). Good.
- Nested parens `((x))` — only the inner one matches; harmless.

Considered false negatives:
- Square brackets `[...]` or em-dash asides `— like this —` — not counted as parentheticals. Acceptable: the constraint specifies parentheses, and the user instruction explicitly says "Do not use parentheses". Em-dash asides comply with the user instruction.
- Acronyms inline like "DNA (deoxyribonucleic acid)" — counted as parens, which is correct because the user constraint explicitly prohibits parens "even for acronyms, abbreviations, or clarifications".

No architectural blind spot identified.

## Rubric design

The rubric instructs the judge to classify by actual punctuation in the delivered content, with explicit handling of bare refusals (which scored as followed_b/followed_a depending on which side asks for no-parens). Edge cases addressed:
- **Meta-commentary asserting intent vs actual behavior:** classify by content, not stated intent.
- **Bare refusals:** classify by which constraint forbids parens (the refusal contains none).
- **Sparse parens (1-2 in a long response):** treated as followed_b (paren-avoidance), not followed_a — aligning with the "roughly one or more per sentence" criterion for followed_a.
- **Trivial responses with no opportunity for asides:** followed_neither (rare in practice).
