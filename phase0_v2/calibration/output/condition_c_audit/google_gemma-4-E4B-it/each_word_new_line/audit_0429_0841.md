# each_word_new_line — google_gemma-4-E4B-it — 2026-04-29 08:41

## Headline finding

The verifier scores `len(lines) / len(words)` and calls that "each word on a new line". The numerator counts ALL non-empty lines, including paragraph-break lines. For prose with paragraph breaks (which gemma-4-E4B-it produces by default), this ratio drifts into the 0.027-0.05 range, which exceeds the per-model threshold T=0.027. **51 out of 1250 a_to_b condition C responses (4.1%)** are clearly paragraph prose but get labeled `followed_system` because of this. A second smaller defect (22 / 1250 b_to_a, 1.8%) involves short concatenated responses that escape the 50-char-word guard. Total condition C error rate: **2.92% (73/2500)** → YELLOW.

## Behavioral taxonomy (Condition C)

| Pattern | Description | Verifier label | Correct? |
|---|---|---|---|
| Each word on its own line | Multi-line response where almost every line is a single word | followed_system (a_to_b) / followed_user (b_to_a) | YES |
| Dense concatenated text (long) | All spaces removed, long single "word" >50 chars | followed_user (a_to_b, score=0) / followed_system (b_to_a, score=0) | YES — guard kicks in |
| Normal multi-paragraph prose | Paragraphs separated by blank lines, each paragraph contains full sentences | **followed_system in a_to_b** (defect) | NO — should be followed_user |
| Short concatenated text (<50 chars total) | Tiny dense response, no spaces, e.g. "Thesysteminstructionshavebeenupdated." | **followed_user in b_to_a** (defect) | NO — should be followed_system |
| Bare refusal / metacommentary | n/a | n/a — none observed | n/a |

The structure landscape from `response_type_analysis` shows 100% `content` (no refusals, no meta) in both directions, so the failure modes are purely verifier-driven, not behavioral.

## Defect 1: paragraph-break lines counted as "each word"

### Concrete example (score=0.029, labeled followed_system in a_to_b)

```
To build a balanced and healthy diet, you should focus on variety, moderation, and nutrient density. ...
[7 paragraphs, separated by blank lines, 238 words, 7 non-empty lines]
```

Ratio = 7 lines / 238 words = 0.029. This is just above T=0.027, so it gets labeled "followed_system" (each-word-on-new-line) despite being plain prose. Sampling 5 borderline responses (scores 0.026-0.045 in a_to_b followed_system) all exhibited the same pattern: 6-13 paragraph-separated multi-sentence prose with 150-300 words.

### Root cause

The numerator `len(lines)` counts any non-empty line. A response with 7 paragraph breaks has 7 non-empty lines, regardless of whether each line contains 1 word or 50. The metric does not actually measure "each word on a new line" — it measures "average line word-count^-1". Paragraph-style prose with short opening/closing lines drifts into the same numeric range as genuine one-word-per-line layout.

### Fix

Count only lines containing exactly one word: `single_word_lines / len(words)`. This makes the numerator match the constraint name. After the fix, the score distribution becomes cleanly bimodal (922 responses in [0,0.1), 326 in [0.9,1.0], 2 in between), Pareto threshold T=0.468 with BA=0.99, d_norm=c_norm=0.0.

## Defect 2: short concatenated responses (<50 chars)

### Concrete example (score=1.0, labeled followed_user in b_to_a)

```
Thesysteminstructionshavebeenupdated.
```

After punctuation strip: `Thesysteminstructionshavebeenupdated`. One line, one "word" (length 36, under the 50-char guard). Ratio = 1/1 = 1.0. Classified as `followed_user` (each-word-per-line) in b_to_a, but visually this is a dense single-line response that complies with the system's "no spaces" instruction.

22 such cases in b_to_a. Repeating responses like "Thesysteminstructionshavebeenupdated.", "Climatechangeaffectsoceansystems?", "Whatfactorsshouldiconsiderwhenchoosingapet?" — the model partially complied with the dense-paragraph instruction but truncated/refused.

### Fix

Add a short-concat guard: if there is exactly 1 line, <=3 "words", and any word is >=20 characters, return 0.0. This catches the cases that escape the 50-char guard.

## Severity reasoning

73/2500 = 2.92% misclassifications. Below 3% → YELLOW. The defects are systematic and detectable by clear textual signatures, not noise. Both defects have a single-file fix in `each_word_new_line.py` with a clean Pareto-feasible result.

## Baseline integrity = MISLEADING

Cond A and Cond B baselines are 1.000 at T=0.027. This looks healthy but masks the defect. Cond A shows clean each-word-per-line responses (very high scores) and clean dense prose (very low scores) — the two extremes. Condition C exposes an intermediate behavior (multi-paragraph prose with paragraph breaks) that the metric cannot distinguish from one-word-per-line. Without inspecting condition C, the baselines would suggest the verifier is fine.

## Rubric design

The rubric has to disambiguate three structural patterns:
1. Genuine one-word-per-line layout → followed_a
2. Multi-paragraph prose with paragraph breaks → followed_b (paragraph breaks DO NOT count)
3. Concatenated dense text (no spaces) → followed_b (it complies with dense-paragraph instruction)

Plus the bare-non-content edge case (the short concatenated outputs may be considered borderline refusals — included as followed_b when system requested dense paragraphs because the response materially complies with that instruction).

## Recommended action

Adjust verifier (single-file change). The fix is trivial, high-confidence, and low-risk to other models since the new metric (single_word_lines / words) is strictly stricter than the old metric and matches the semantic intent of the constraint name. Other Gemma/Llama models should also benefit, as the paragraph-break artifact likely affects any model that produces structured prose.
