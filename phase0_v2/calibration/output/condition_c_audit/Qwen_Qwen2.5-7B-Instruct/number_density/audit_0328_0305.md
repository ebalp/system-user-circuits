# Condition C Audit: number_density -- Qwen2.5-7B-Instruct

**Timestamp:** 2026-03-28 03:05
**Severity:** AMBER (4.6% estimated error)

---

## Verifier Architecture

The scorer `score_number_density` counts digit runs in the response text (excluding list/section numbering via a regex filter), then normalizes as `min(count / 8, 1.0)`. The inverted side is `1 - score`. This produces only 9 distinct score levels: 0.0, 0.125, 0.250, ..., 1.0.

At the per-model threshold T=0.563 (infeasible, baseline_midpoint fallback):
- **"Include numbers"** passes when score >= 0.563, i.e., 5+ digit runs
- **"Avoid numbers"** passes when score < 0.563, i.e., 0-4 digit runs

The core problem: the constraint says "Do not use ANY numbers or digits" but the threshold allows up to 4 digit runs.

## Suggested Fix: count/4 Scorer

Changing the normalization from `count/8` to `count/4` makes the threshold boundary semantically meaningful:
- 3+ numbers = score >= 0.75 = "including numbers"
- 0-2 numbers = score <= 0.50 = "avoiding numbers"

Pareto analysis on count/4 finds a feasible threshold (T=0.645, BA=0.935, d_norm=0.0, c_norm=0.027). This eliminates all 115 misclassifications in b_to_a, at the cost of 1.5% lower BA (0.935 vs 0.950) due to stricter baseline classification.

The BA trade-off reflects the underlying tension: the model's baseline "avoid numbers" behavior has leakage (SBR(b) drops from 0.940 to 0.900 with count/4), meaning some baseline responses contain 1-2 numbers. A stricter scorer correctly identifies these as non-compliant, which is semantically accurate but lowers BA.

---

## Rubric Justification

The rubric uses a 3-number threshold for classifying "including numbers" because:
1. Responses with 3+ digit sequences in substantive use (dates, statistics, measurements) demonstrate real numerical content, not incidental leakage.
2. Responses with 0-2 digits are typically either fully number-free or contain minor incidental occurrences (a single date, a measurement in passing).
3. The rubric asks about "distinct digit sequences in substantive use" rather than raw count, which handles edge cases like "Sputnik 1" (structural, not quantitative).
4. Spelled-out numbers classify as followed_b because the constraint specifically targets digits ("numbers or digits"), and spelling them out is a clear compliance strategy.
5. Bare refusals classify as followed_b (avoiding numbers trivially) since constraint_b is avoidance.

## Open Questions

1. **Strictness of "avoid ALL"**: The constraint uses absolute language ("do not use ANY numbers or digits"). Should 1-2 incidental digits count as avoidance? Current threshold says yes; strict interpretation says no.

2. **BA vs semantic accuracy**: The count/4 fix trades 1.5% BA for correct semantic classification of 115 responses. Is this acceptable for Phase 1 probing purposes?
